# Accessibility Review — Nutrition

## Overall verdict

Le plancher d’accessibilité est trop mince et trop sûr de lui : il « vérifie » un seul couple (`ink-primary` / `surface-base`) alors que plusieurs paires porteuses n’ont aucun cible WCAG, et que `ink-disabled` échoue en texte AA. Les règles photo couvrent recettes + bandeaux décoratifs **si un nom visible reste**, mais restent muettes sur les vignettes OFF, un titre vide, et les pastilles Plan. Extraire uniquement ces spines vers l’architecture / les stories livrerait un UI qui rate 1.4.1 (priorité), 1.1.1 (produits) et plusieurs cibles tactiles / focus.

## Findings

- **critical** Contraste : le Floor sur-déclare AA (EXPERIENCE.md Accessibility Floor ; DESIGN.md Colors). Seul `{colors.ink-primary}` / `{colors.surface-base}` a une cible (≥ 4.5:1, ~15.3:1 réel). `ink-secondary` (~9.3), `ink-warm` (~12.8) et `accent-positive` sur `surface-base` (~7.8, FAB icône ~7.8) passent mais **sans cible écrite**. `ink-disabled` `#6B756B` fait 3.49:1 sur `surface-base`, 3.03:1 sur `surface-raised`, 2.56:1 sur `surface-overlay` — AA texte échoué. Le Floor + le mock catalogue (`::placeholder` `ink-disabled` sur overlay) + le mock Plan (créneau vide `#6B756B` à 15 px) autorisent du texte illisible. *Fix:* cibles WCAG par rôle (texte 4.5, UI 3.1) pour chaque token porteur ; interdire `ink-disabled` comme encre de CTA / placeholder / empty slot.

- **critical** Priorité = couleur seule pour l’œil (DESIGN.md Priority badge + Do’s ; EXPERIENCE.md Floor ; mockups/products-catalog.html, shell-nav.html). DESIGN exige un « label texte accessible » ; le Floor réduit ça à `aria-label` « Priorité haute / moyenne / basse » ; les mocks n’ont **ni** texte **ni** aria — pastille 10 px verte / jaune / grise. Luminance `priority-green` ≈ `priority-gray` (0.33 vs 0.34) : en niveaux de gris / deutéranopie, haute et basse se confondent. L’`aria-label` aide le lecteur d’écran, pas l’utilisateur voyant daltonien (WCAG 1.4.1). *Fix:* label visible (mot ou initiale) collé à la pastille, pas seulement aria ; ne pas traiter le Floor comme suffisant pour 1.4.1.

- **high** Vignettes OFF sans règle alt (EXPERIENCE.md Floor l.230 ; ProductThumb / ProductCard ; mockups/products-catalog.html). Floor : photos recettes `alt` = titre ; bandeaux / placeholders / pictos catégorie `aria-hidden`. **Aucune règle** pour l’image OFF (liste, preview scan, import). Les mocks inventent `role="img" aria-label="{nom}"` (doublon du titre) et `aria-hidden` sur le fallback picto. Architecture qui n’extrait que le Floor = images sans `alt` (1.1.1) ou bricolage contradictoire. *Fix:* trancher dans le Floor — décoratif (`alt=""` / `aria-hidden`, le nom générique suffit) **ou** `alt` = nom produit / marque OFF — et l’écrire.

- **high** Permission galerie absente (EXPERIENCE.md PhotoPrompt, State « Caméra refusée », Voice, iOS, Flow 6). Caméra refusée → galerie + message factuel : spécifié. **Refus galerie / fichiers** : aucun état, aucun message, aucun repli (Plus tard seulement ?). iOS sépare bien scan code-barres (saisie, pas de caméra) et photo recette (picker système) — ce couple-là tient. *Fix:* ajouter l’état « galerie / fichiers refusés » sans inventer ici le copy ; ne pas laisser Caméra comme seule issue.

- **high** Mode Courses — coché : encodage et nom accessible (DESIGN.md shopping-row ; EXPERIENCE.md Surface 4 + Floor ; mockups/shopping-mode.html). Spine : opacité 0.55 + barré (pas couleur seule — le barré sauve 1.4.1) ; Floor : `aria` sur checkboxes. Mode Courses : tap **ligne entière** → coche ; `ShoppingRow` : zone 52 px vs tap nom = éditer. Le mock n’a ni `role="checkbox"` ni `aria-checked` ; badge « manuel » `#6B6B6B` / `#2A2A2A` ~2.7:1. Opacité 0.55 sur `ink-primary` reste ~5.5:1 ; sur `ink-secondary` tombe à ~3.8:1. *Fix:* état `aria-checked` (ligne ou checkbox) + nom ; conserver le barré comme encodage non-couleur ; cible de contraste après fade.

- **high** Focus visible cantonné au « debug desktop » (EXPERIENCE.md Floor). WCAG 2.4.7 n’est pas un luxe Paramètres. PWA + clavier / switch / TalkBack+clavier : bottom nav, FAB, chips, PhotoPrompt, sheets. *Fix:* focus ring visible sur **tout** contrôle, toutes surfaces, pas seulement Paramètres.

- **high** Cibles tactiles : vignettes vs cartes (DESIGN.md Layout, recipe-thumb 72, plan-slot-thumb 40, variant chips, Photo prompt ; EXPERIENCE.md WeekGrid / RecipeHero ; mockups/recipes-list.html, meal-plan.html, photo-prompt.html). Le Floor dit tout contrôle ≥ 44×44 (52 en Mode Courses). Les boutons PhotoPrompt et le FAB tiennent. Rien n’écrit que la **carte / le créneau** est la hit zone et que 72 / 40 px sont de l’image, pas le contrôle — un extracteur fera des pastilles Plan 40 px cliquables. Chips variante (`padding: 4px 10px`), lien « Changer la photo », jours 44×~40, engrenage Recettes `aria-hidden` sans 44 px (shell-nav a 44 + `aria-label`, pas DESIGN). Le bandeau `aria-hidden` + `h1` distinct : **correct**, ne remplace pas le titre. *Fix:* hit target = carte / créneau / ligne ≥ 44 ; chips et actions photo ≥ 44 ; nom accessible sur l’engrenage partout.

- **high** ScannerView « Auto-start caméra » vs iOS sans scan (EXPERIENCE.md ScannerView, Responsive, Flow 2). iOS : pas de scan barcode → « Saisir le code ». Le composant dit quand même auto-start. Risque : prompt caméra iOS inutile / refusé, puis saisie — alors que la plateforme doit **skip** la caméra. Alternative saisie toujours visible : bon. Overlay `rgba(0,0,0,0.65)` + hint : **aucune** couleur de hint, aucun ratio (le trou de visée = flux caméra incontrôlé). *Fix:* qualifier Auto-start = Android ; iOS = saisie d’emblée ; token + ratio pour hint **hors** cadre, ou hint hors overlay.

- **medium** Macros : chiffres oui, état non (DESIGN.md Macro progress bar ; EXPERIENCE.md Surface 3 + Floor ; mockups/macro-synthesis.html). Label « Protéines 142 / 150 g » + aria valeur/objectif : l’utilisateur peut comparer. L’état sous / atteint (±5 %) / dépassé n’est **que** la couleur (`macro-under` / `met` / `over`, luminances 0.40 / 0.44 / 0.41 — proches). Objectif absent = « valeur seule », plus rien à comparer. *Fix:* aria (et idéalement texte) de l’état ; ne pas compter sur la teinte.

- **medium** Photos recettes : `alt` = titre — titre vide / doublon (EXPERIENCE.md Floor ; DESIGN.md Recipe card / hero ; mockups/recipes-list.html, meal-plan.html). Le data-model a `title: string` (pas optionnel) mais n’interdit pas `""`. Floor sans fallback → `alt=""` silencieux **et** titre vide = carte anonyme. Bandeaux / placeholders / pictos `aria-hidden` : le nom restant **suffit** (liste, détail, PhotoPrompt sous-titre, Plan). `PlanSlotThumb` photo : **pas** dans le Floor (ni alt, ni hidden) — les mocks dupliquent `aria-label` = nom. Photo + titre visible = double annonce. *Fix:* fallback alt si titre blanc (sans inventer le libellé) ; pastille Plan = même règle que placeholder (`aria-hidden`) ou alt unique ; éviter double nom.

- **medium** PhotoPrompt — ordre de focus incomplet (EXPERIENCE.md Floor, PhotoPrompt, iOS ; mockups/photo-prompt.html). Ordre Galerie → Caméra → Plus tard : le DOM du mock le suit. Manque : focus initial (titre vs premier bouton), retour du picker système, et ordre **quand Caméra disparaît** (permission refusée). *Fix:* focus initial + restore ; si Caméra retiré, ne pas le laisser dans le tab order.

- **medium** `prefers-reduced-motion` trop étroit (EXPERIENCE.md Floor, Interaction, Mode Courses). Seules les transitions > 100 ms. Sheets slide-up, pull-to-refresh, swipe jours, auto-start scanner : hors règle. Mode Courses sans anim de coche : bon. Bandeaux statiques : bon. *Fix:* étendre reduced-motion aux sheets / swipe / scan chrome.

- **medium** Toasts et long-press sans équivalent (EXPERIENCE.md Voice, Interaction, BottomSheet). « Produit ajouté. », « Photo non enregistrée. » : pas de live region. Long-press menus (archiver / supprimer) : pas d’équivalent clavier. Focus trap sheet **seulement** « si formulaire » — pickers recette / variante exclus. *Fix:* `aria-live` pour toasts ; menu aussi via clavier ; trap sur tout sheet interactif.

- **medium** Score et étoiles sans nom (DESIGN.md score-chip, Variant picker ; mockups/products-catalog.html, recipes-list.html, meal-plan.html). Chip « 82 » neutre, pas de `aria-label` « score ». `★★★★` / « Lavash ★★★★ » : pas d’équivalent texte. *Fix:* nom accessible (score, note /5).

- **low** Paires sans cible alors qu’elles passent (DESIGN.md Colors / recipe-placeholder / Shapes). `ink-secondary`, `ink-warm`, `accent-positive` sur surfaces : AA OK, non documenté. Trait placeholder `ink-warm` / overlay ~9.4:1, décoratif `aria-hidden` : OK. Interdiction titre overlay photo : prévient un couple illisible, **sans** recette si un badge (DLC, variante) atterrit plus tard sur hero / scan. `accent-positive-muted` picto ~3.01:1 sur raised (limite UI 3:1). *Fix:* cibles écrites ; interdire texte/badge overlay photo partout, pas seulement liste.

- **low** Mocks magasin / shell encore sur l’ancienne palette (mockups/shopping-mode.html, shell-nav.html, macro-synthesis.html vs DESIGN.md). `#121212` / `#7CB87C` / `#B0B0B0` : les spines gagnent, mais un extracteur « pixel-perfect mock » réintroduit tokens et contrastes non audités (badge manuel). *Fix:* les stories lisent les spines, pas ces trois mocks, pour la couleur.

## Preamble

Relecture adverse du couple spine **sans le modifier** : `DESIGN.md` (tokens, Components, Do’s), `EXPERIENCE.md` (Floor + patterns + plateforme + flows), `.memlog.md`, et les sept HTML de `mockups/`. Contrastes recalculés (WCAG 2.x relative luminance), pas ceux « vérifiés » par le Floor. Angle : qu’est-ce qui part en stories si on n’extrait **que** ces deux documents. Pas de décision produit inventée (pas de copy galerie-refusée, pas d’interdiction titre vide que le data-model n’écrit pas). Les mocks ne sont pas le contrat — ils montrent déjà les trous que le Floor laisse ouverts (pastilles nues, alt OFF bricolé, Mode Courses sans checkbox, gear `aria-hidden`).
