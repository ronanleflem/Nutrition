# Edge-Case Review — Nutrition

## Overall verdict

Le contrat maison / magasin est serré sur les cinq onglets et le happy path photo recette / vignette OFF, mais il ne classe pas les surfaces d’entrée réelles après l’épic 12 (`/home`, `/onboarding`) et ne dit rien de la restauration ou de la fusion des blobs. Un extracteur qui ne lit que les spines inventera l’Accueil, sautera le prompt photo à la première recette, et pourra afficher une image cassée ou écraser une photo locale à l’import.

## Findings

- **critical** Accueil `/home` et onboarding `/onboarding` hors contrat maison / magasin (EXPERIENCE.md Information Architecture, Visuels persistants, Cold start ; DESIGN.md Brand & Style, Surface banner). Après l’épic 12 l’app ouvre `/onboarding` puis `/home` (titre → Accueil ; option masquer au démarrage). Les spines n’ont ni route, ni bandeau, ni photo : cold start = dernier onglet ou Garde-manger. L’Accueil actuel liste repas / courses / DLC / rappel export en texte seul. Rien ne dit si Accueil est maison (bandeau + pastilles recette + vignettes OFF) ou magasin nu, ni si le wizard (chrome masqué comme le Mode Courses) a droit à une illustration. *Fix:* ajouter `/home` et `/onboarding` à l’IA ; classer chaque surface (bandeau oui/non, photos oui/non) ; aligner le cold start sur l’épic 12.

- **high** Première recette onboarding sans PhotoPrompt (EXPERIENCE.md PhotoPrompt, Flow 6, Surface 2 ; app `onboarding.service` / `recipe-form-page` `from=onboarding`). Le prompt est « post-enregistrement d’une recette », recette déjà persistée. L’omelette template et la recette custom (`/recipes/new?from=onboarding`) enchaînent vers `/home` sans Galerie / Caméra / Plus tard. Branche create du contrat visuel : jamais marchée pour le premier plat. *Fix:* commit — prompt après omelette et après custom (puis Accueil), ou skip explicite + placeholder + ajout depuis le détail.

- **high** Restauration d’un blob manquant (EXPERIENCE.md Visuels persistants Backup ; PRD FR-23, UJ-3 ; State « Recette sans photo » / « Image OFF absente »). L’export inclut toujours les blobs ; l’import ne dit pas quoi faire si `photoId` / vignette OFF pointe vers un blob absent (fichier partiel, export pré-photos, truncate + import). Ni placeholder, ni échec d’import, ni résumé « N photos manquantes ». Risque : `<img>` cassée (interdit : pas de case vide) ou recette / produit visuellement orphelin après UJ-3. *Fix:* blob manquant ≡ sans photo (placeholder plat / picto catégorie) ; le résumé d’import compte les visuels restaurés vs manquants ; ne pas faire échouer tout l’import.

- **high** Fusion import des photos (EXPERIENCE.md Backup ; PRD FR-23 §10.4 / addendum merge ; Architecture AD-10). Recette même `id` → REPLACE recette + ingrédients ; Produit → UPDATE champs ; blobs absents des tables de fusion. Local a une photo, import sans blob : perte ? Les deux ont une photo : laquelle gagne ? Vignette OFF orpheline ou doublon après remap d’id ? « Aucune perte des données locales non couvertes par le fichier » ne cite pas les blobs. *Fix:* étendre §10 — recette : photo import gagne si présente, sinon conserver la locale ; OFF : blob suit la ref fusionnée ; replace-all : fichier = source de vérité, blob absent → fallback visuel.

- **high** Échec quota / écriture au *changement* de photo (EXPERIENCE.md State « Photo / quota échoué », RecipeHero, Flow 6). L’état unique dit : recette intacte · **placeholder** · « Photo non enregistrée. » Correct à la *première* pose. Au *remplacement* depuis le détail, « placeholder » efface la photo déjà affichée alors que le blob précédent est encore là. *Fix:* scinder add vs replace — add échoué → placeholder ; replace échoué → garder l’ancienne photo + le même message.

- **high** Sorties PhotoPrompt hors des trois actions (EXPERIENCE.md PhotoPrompt, Flow 6, Interaction ; DESIGN.md Photo prompt). Couvertes : Galerie, Caméra, Plus tard, caméra refusée, quota. Pas couvertes : retour système / geste arrière (écran plein cadre, pas une sheet) ; annulation du picker galerie / caméra sans fichier ; mise en arrière-plan au milieu du picker. La recette est déjà sauvée : équivalent Plus tard, ou piège sur l’écran prompt ? *Fix:* toute sortie sans fichier = Plus tard (placeholder, liste ou détail) ; retour du picker vide = rester sur le prompt.

- **medium** Titre vide à la création (EXPERIENCE.md Floor `alt` = titre, Flow 6, PhotoPrompt ; DESIGN.md Photo prompt ; mock `photo-prompt.html` « Wrap poulet est enregistré »). Le spine ne rend pas le titre obligatoire avant persist + prompt. Titre `""` : copy du prompt sans nom ; `alt` vide ; carte anonyme + hero. L’app bloque aujourd’hui (`pattern(/\S/)`) — ce n’est pas le contrat. *Fix:* titre non blanc requis avant enregistrement (donc avant prompt) ; si un titre vide existait déjà, fallback `alt` + copy prompt sans dépendre du nom.

- **medium** Galerie / fichiers refusés (EXPERIENCE.md State « Caméra refusée », PhotoPrompt, iOS). Caméra refusée → galerie + message. Refus Photos / fichiers (ou picker vide iOS « Accès limité ») : aucun état, aucun message, Caméra reste la seule issue si la galerie est morte. *Fix:* état « galerie indisponible » ; Plus tard toujours possible ; ne pas laisser Caméra comme unique repli.

- **medium** FR-24 rappel vs bandeau de surface vs « aucun bandeau » magasin (DESIGN.md Brand & Style, Layout bandeau ; EXPERIENCE.md Visuels persistants, Surface 4 ; PRD FR-24). Le rappel 30 jours n’existe pas dans les spines. L’app le pose dans le shell (sous le header, hors Mode Courses / onboarding) : il s’empile avec le bandeau 100 px sur Garde-manger / Recettes / Plan, et apparaît sur Courses / Objectifs / Paramètres — surfaces déclarées sans bandeau. Accueil a en plus une carte Sauvegarde. *Fix:* le rappel FR-24 n’est pas un `SurfaceBanner` ; le classer (bandeau texte shell, une surface max, masqué en magasin nu) et régler l’empilement avec le bandeau illustré.

- **medium** « Aucun bandeau » liste Courses vs `RegenerateBanner` + liste vide (DESIGN.md magasin nu ; EXPERIENCE.md Surface 4, State « Plan modifié », EmptyState). `RegenerateBanner` est un bandeau texte (« Le plan a changé… ») sur la liste normale, interdit de photos. « Aucun bandeau » peut le faire supprimer. Liste vide : EmptyState n’est listé que pour Catalogue / Recettes / Plan ; Courses vide + plan périmé sans items auto → pas de banner (« si items auto existants ») et pas de CTA « Générer » dans le spine. Mode Courses à 0 item : pas d’état. *Fix:* `RegenerateBanner` = exception texte, pas illustration ; EmptyState Courses (pas de plan vs plan sans items) ; Mode Courses interdit ou no-op si liste vide.

- **medium** Vignettes hors listes maison (EXPERIENCE.md Picker recette, Surface 3, PlanSlotThumb ; DESIGN.md sous-écrans sans bandeau ; Accueil cartes). Bandeau : sous-écrans = non (synthèse, picker, détail produit : OK). Photos recettes : le picker (« Je reconnais mon plat ») et les lignes synthèse / carte Accueil « Repas du jour » n’ont aucune règle vignette vs texte. Détail produit : pas de hero OFF. *Fix:* picker recette = mêmes thumbs que la liste (ou texte assumé) ; synthèse et Accueil : pastille ou texte seul ; détail produit : pas de hero (picto / rien).

- **medium** Export chiffré plus lourd (EXPERIENCE.md Backup ; PRD FR-22, UJ-3). « Fichier plus lourd accepté » n’est pas un parcours : pas de taille estimée, pas de progression AES-GCM, pas d’échec mémoire / share iOS, pas de copy. *Fix:* accepter le poids ne dispense pas d’un état d’échec (même famille que « Téléchargement impossible ») et, si le fichier dépasse un seuil, d’un avertissement avant chiffrement.

- **low** Retirer la photo sans confirmation (EXPERIENCE.md RecipeHero, Dialog modal). Destructif listé : archiver produit référencé, supprimer recette planifiée. Retrait photo : instantané ou dialog ? Pas d’annulation. *Fix:* retrait immédiat + toast, ou dialog court ; après retrait = placeholder partout.

- **low** Ref préférée archivée → quelle vignette (DESIGN.md Product card ; EXPERIENCE.md ProductCard, « photo OFF de la ref préférée »). Préférée archivée, d’autres refs ont une image : vignette de l’archivée, picto, ou autre ref ? *Fix:* si la préférée n’a plus d’image exploitable → picto (même règle que « pas de préférée »).

- **low** Format image illisible (EXPERIENCE.md import resize WebP, State quota). HEIC / vidéo / fichier que le resize ne décode pas : pas d’état distinct. *Fix:* même issue que quota — recette intacte, photo précédente conservée si replace, « Photo non enregistrée. »

## Preamble

Parcours marchés comme contrat (spines + mocks + PRD §2.3 / FR-22–24 + project-context + surfaces E12 dans l’app), sans modifier les spines. Branches : photo recette (create → prompt Galerie / Caméra / Plus tard ; édition détail ; caméra refusée ; quota ; titre vide ; variante vs famille ; placeholder vs vide) ; vignettes OFF (image absente, import, sans préférée, photo user interdite) ; bandeaux (liste vide vs remplie, sous-écrans, Accueil `/home`, onboarding) ; Mode Courses / liste (zéro image vs régénérer, liste vide) ; backup (blobs toujours exportés, restore blob manquant, taille chiffrée, fusion photos) ; preview scan + iOS sans caméra scan ; Accueil / première recette. Seuls les chemins sans issue écrite sont listés.
